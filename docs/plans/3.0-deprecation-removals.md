# Plan: 3.0 deprecation removals

Target release: **3.0**
Status: **Breaking by design.** This is the cleanup release that collects
everything 2.x kept alive behind a warning.
Prerequisite: 2.0 ships [.env configuration](env-file-config.md) with both
config fallbacks warning throughout 2.x.

## Principle

Nothing lands here that didn't warn in 2.x. If a removal below has no
corresponding runtime deprecation warning shipped in 2.0, add the warning to 2.x
first — this release should surprise no one who ran their app and read the
console.

## 1. JSON config files

Remove the `app/config/*.json` convention entirely.

| Remove | Where |
| ------ | ----- |
| `getConfig()` JSON loader, `host` key matching, per-file parse loop | [`init/config.js:134-177`](../../init/config.js#L134-L177) |
| The deprecated-path `extend()` from the resolution chain | `init/config.js` |
| Root-level `host` config key and `app.config.host` | `init/config.js`, `README.md` |
| Config-file references throughout the docs | `README.md`, ~30 mentions |

`host` goes away rather than staying vestigial — with the JSON loader gone it
selects nothing. It was never used by the framework for anything else (grep
confirms no `config.host` reads in `lib/`).

Keep a startup check for one release: if `app/config/*.json` exists, log an
error explaining that JSON config was removed in 3.0 and pointing at `.env`.
A silently-ignored config directory is a much worse failure than a loud one —
someone upgrading with a `citizen.json` full of settings would otherwise get a
server on port 80 in production mode with no explanation.

## 2. `citizen` node in `start()` options

Framework settings come from the environment only.

| Remove | Where |
| ------ | ----- |
| `citizen` node handling in the `applicationStart` merge | [`lib/server.js:47`](../../lib/server.js#L47) |
| The 2.x deprecation warning that names replacement env vars | `lib/server.js` |
| `start()` HTTPS/PFX examples | `README.md` (Startup configuration section) |

Same treatment as above: rather than silently dropping the node, throw at
startup if `options.citizen` is present. Ignoring it would mean an app that
configured HTTPS via `start()` boots plaintext on port 80 — a security failure,
not an inconvenience. `start()` retains app-owned nodes, unchanged.

## 3. `X-Forwarded-*` headers

Deprecated in 1.0 (see [CHANGELOG](../../CHANGELOG.md#L31-L32)) in favor of the
standard `Forwarded` header, still supported today:

- [`lib/router.js:16`](../../lib/router.js#L16) — `x-forwarded-proto`,
  `x-forwarded-host` fallbacks
- [`lib/server.js:609`](../../lib/server.js#L609) — `x-forwarded-for` fallback

Removing these is three expression edits, but it is **the riskiest item here**,
because the failure is silent and environmental: an app behind a proxy that only
sends `X-Forwarded-*` starts resolving the wrong protocol and host, which breaks
secure-cookie handling and CORS origin checks without an error. Unlike the config
removals there's no way to detect the bad state at startup — the proxy config
isn't visible to citizen.

Mitigations, in order of preference:

1. Ship a runtime warning in 2.x, logged once per process, when an
   `X-Forwarded-*` header is used *and* no `Forwarded` header is present. This is
   the missing precondition — the 1.0 deprecation was CHANGELOG-only.
2. Failing that, defer to 3.1+ and keep the fallbacks in 3.0.

Do not remove these in 3.0 without (1) having shipped in 2.x.

## 4. Sweep for the rest

Before finalizing, audit for anything else marked "still supported" that has
outlived its purpose — with one exclusion already decided:

**Views in subfolders are not deprecated and stay supported.** The CHANGELOG 1.0
framing ("Old pattern (still supported)") makes a permanent, equally valid layout
choice read like a leftover awaiting removal. Fix the wording in `README.md` so
both layouts are presented as alternatives, and do not add a deprecation warning
for it in 2.x.

## Work

Small. Removals are mostly deletion plus the guard rails that make them loud:

| # | Change | Size |
| - | ------ | ---- |
| 1 | Delete JSON loader + `host`; add "config removed" startup error | ~60 lines deleted, ~10 added |
| 2 | Delete `start({ citizen })` handling; throw if present | ~10 lines |
| 3 | Delete `X-Forwarded-*` fallbacks — **only if the 2.x warning shipped** | ~3 lines |
| 4 | Prune both config conventions from the docs | `README.md`, the bulk of the work |
| 5 | Migration section in the CHANGELOG: every removed key → its replacement | small |

The config-resolution test suite added in 2.0 shrinks with the code: delete the
JSON-path and both-present cases, and add two cases asserting the new startup
errors fire.
